# 🛡️ Telhawk Galen — Security Policy

## Overview

Security is at the core of Telhawk Galen.

Galen is an AI-powered security testing solution designed to help developers identify potential vulnerabilities in their applications using AI-assisted workflows.

We welcome responsible security research and encourage developers, beta testers, and security researchers to report potential vulnerabilities.

This policy explains how to report security concerns involving Galen and how security-related information should be handled within our developer community.

---

## 🔐 Reporting a Security Vulnerability in Galen

If you discover a potential security vulnerability in Telhawk Galen itself, please report it privately.

**Do not create a public GitHub Issue or Discussion containing details of an exploitable vulnerability.**

Instead, use GitHub's Private Vulnerability Reporting feature.

### How to Submit a Private Report

1. Visit the Telhawk Galen Community repository.
2. Select the **Security** tab.
3. Select **Advisories**.
4. Click **Report a vulnerability**.
5. Describe the potential vulnerability and submit your report.

Repository:
https://github.com/telhawk-systems/galen-community

When submitting a report, please include:

- A description of the vulnerability.
- The Galen version being used, if known.
- Steps to reproduce the issue.
- Potential security impact.
- Screenshots or error messages, if applicable.
- Any recommended mitigation.

Please remove passwords, API keys, authentication tokens, customer information, and other sensitive data before submitting.

Telhawk will review submitted reports and determine appropriate next steps.

---

## 🔎 Vulnerabilities Discovered in Applications Tested by Galen

Galen is designed to help developers identify security vulnerabilities in applications they are building or maintaining.

These findings are different from vulnerabilities in Galen itself.

If Galen identifies a vulnerability in your application:

1. Review the finding and validate it where appropriate.
2. Follow your organization's security remediation procedures.
3. Avoid publishing sensitive vulnerability details.
4. Do not share application source code, credentials, or confidential customer information in public GitHub Discussions or Issues.

Security findings involving third-party applications should be reported through the affected organization's authorized security disclosure channels.

**The Telhawk Galen Community is not a public vulnerability disclosure platform for third-party applications.**

---

## 🐛 Reporting General Bugs

Not every issue is a security vulnerability.

For general software bugs, installation problems, unexpected behavior, or technical errors involving Galen, please use our GitHub Issue reporting system.

Visit:

https://github.com/telhawk-systems/galen-community/issues

Select **New Issue** and choose the **Galen Bug Report** template.

Examples include:

- Installation or configuration problems.
- Unexpected error messages.
- Problems running security analysis.
- Compatibility issues with AI coding assistants.
- Unexpected application behavior.
- Documentation errors.

Do not include confidential information in public bug reports.

## 🤝 Responsible Security Research

We encourage responsible security research conducted in authorized environments.

Community participants should:

- Test only applications and systems they own or are explicitly authorized to assess.
- Respect the privacy and security of other users.
- Avoid accessing, modifying, or disclosing information belonging to others.
- Avoid activities that disrupt Telhawk services or infrastructure.
- Report potential Galen vulnerabilities privately.
- Allow Telhawk a reasonable opportunity to investigate and address reported vulnerabilities before public disclosure.

Participation in the beta program does not grant permission to test Telhawk infrastructure or third-party systems without authorization.

---

## 🔒 Protecting Sensitive Information

Never publish the following information in GitHub Issues or Discussions:

- API keys or authentication tokens.
- Passwords or private credentials.
- Confidential application source code.
- Customer or personal information.
- Private security assessment reports.
- Sensitive infrastructure configurations.
- Exploit details involving unpatched vulnerabilities.

If sensitive information is accidentally published, notify the repository maintainers promptly.

Deleting a GitHub comment or issue does not necessarily eliminate all copies of exposed information. Compromised credentials should be revoked or rotated.

---

## 🧪 Developer Beta Program

Telhawk Galen is currently being offered through a developer beta program.

Beta software may contain bugs, incomplete features, or unexpected behavior.

Participants should:

- Follow the official Galen setup instructions.
- Review commands suggested by their AI coding assistants.
- Avoid executing unfamiliar commands without understanding their effects.
- Maintain appropriate backups of important projects.
- Use authorized testing environments.
- Report problems through the appropriate GitHub channels.

Galen is intended to assist security testing and does not guarantee that an application is free from vulnerabilities.

Developers remain responsible for reviewing findings and maintaining appropriate application security practices.

---

## 📢 Security Communications

Important security announcements, product updates, and beta-related notices may be published through the Telhawk Galen Developer Beta Community.

Security-sensitive information will be handled through appropriate private reporting channels.

Public disclosure of confirmed vulnerabilities will be coordinated by Telhawk when appropriate.
